Cloth simulation.

A grid of point masses joined by springs, stepped with Verlet integration. Grab it, fling it, slice it, or move the pins and watch it settle.

0 points 0 springs 0 fps 0 ms/frame
Drag to pull and throw Right-drag or Shift+drag to cut Double-click a point to pin or unpin it Keys: G grab · C cut · W wind · T tearing · R reset
01 · Integrate

Verlet integration

Each point stores only its current and previous position. Velocity is implied by the difference, so a step is x' = x + (x − x₀)·damping + g·dt². No velocities to drift out of sync, and constraints can move points directly.

02 · Constrain

Spring constraints

Neighbouring points are linked by springs with a rest length. Each pass pulls stretched springs back to length, splitting the correction between both ends. Like the original, springs only resist stretching, so the cloth can bunch and fold.

03 · Break

Tearing and pins

When tearing is on, a spring stretched past three times its rest length snaps. Pinned points ignore gravity and corrections, and dragging one moves the pin itself. Spring colour shows strain.

Original

I first wrote this in Luau for Roblox: the cloth is an EditableMesh whose vertices are driven by the solver, with sphere and cylinder colliders, a custom vector type to cut allocation, and a benchmarking mode. Rendering the mesh, not the physics, turned out to be the bottleneck. This page is a lightweight JavaScript port of the same solver, drawn as plain lines on a canvas. It keeps the cloth in flat typed arrays, uses a square-root-free spring correction, interpolates between physics steps for high-refresh displays, and puts the solver to sleep once the cloth settles, so a frame costs well under a millisecond.
